# Plan: Langcliffe Inbound Email Processing

## Context

Langcliffe is a business broker that sends deal-flow teaser emails to registered buyers. Acquiro users forward these emails to their AI agent's inbox (`agent@acquiro.ai`). Acquiro parses the opportunities, scores them against the user's criteria, and — if matched — sends an introductory reply to Langcliffe on the user's behalf. Matched Langcliffe listings do NOT appear in the normal match dashboard (silent outreach only).

---

## Prerequisites (user must complete before code ships)

### 1. Domain
Acquire a domain for Acquiro (e.g. `acquiro.ai`).

### 2. SendGrid setup
- Create a SendGrid account.
- **Inbound Parse:** Set MX record for the domain to `mx.sendgrid.net`. Configure Inbound Parse webhook URL → `https://<railway-url>/webhook/inbound-email`.
- **Sending:** Authenticate the domain (SPF + DKIM) so replies from `agent@acquiro.ai` pass spam filters.
- Add `SENDGRID_API_KEY` to Railway env vars.

### 3. Bubble schema additions
| Table | New field | Type |
|---|---|---|
| `Agents` | `email_text` | Agent's email address, e.g. `sophia@acquiro.ai` |
| `Buyer_Info` | `company_overview_text` | Buyer introduction paragraph used in outreach emails |
| `LangcliffeOutreach` *(new table)* | `listing_id_text`, `user_user`, `sent_at_date` | Dedup tracker: one record per listing per user |

### 4. Per-user setup
- Populate `Agents.email_text` in Bubble for each agent.
- Each user sets up a forward rule from their Langcliffe email account to their agent's address.
- Fill in `Buyer_Info.company_overview_text` for each subscribed user.

## Architecture

```
Langcliffe → user forwards → sophia@acquiro.ai
                                    │
                          SendGrid Inbound Parse
                                    │
                    POST /webhook/inbound-email
                                    │
                    langcliffeParser.js
                    (OpenAI extracts listings array)
                                    │
                    processAndIndexListing()    ← existing
                    (Bubble + Pinecone, source='langcliffe')
                                    │
                    langcliffeResponder.js
                    (embed + score vs buyer profile)
                                    │
                    score >= 0.50? ──Yes──► send reply via SendGrid
                         │                 record LangcliffeOutreach
                        No ──► skip
```

Daily pipeline (`generateMatchesForUser`) is modified to exclude `source='langcliffe'` listings from Pinecone results so they never surface in the dashboard.

```js
export async function processLangcliffeListings({ userId, bubbleIds, replyTo, originalSubject }) {
  // 1. getBuyerInfo(userId) — criteria + company_overview_text
  // 2. getAgentForUser(userId) — name + email_text

  //    a. Embed listing golden string
  //    b. Embed buyer golden string
  //    c. Cosine similarity + scoreFinancials() + sector boost

  //       - Generate outreach email body via OpenAI
  //       - Send via SendGrid API (from: agentEmail, to: replyTo)
  //       - createOutreachRecord(userId, listingId)
}
```

Outreach email structure (assembled in code, body generated by OpenAI):
1. "Hi, I'm {agentName}, reaching out on behalf of {companyName}."
2. Company overview from `company_overview_text`
3. Why this specific opportunity is interesting
4. Request for more info / introductory meeting

## Scoring approach

Direct embedding comparison (no full Pinecone index query needed):
1. Embed Langcliffe listing golden string with `text-embedding-3-small`
2. Embed buyer profile golden string (same format as `matcher.js:buildGoldenString`)
3. Cosine similarity between the two vectors
4. Apply `scoreFinancials()` adjustment and sector boost (reuse existing logic from `matcher.js`)
5. Threshold >= 0.50 → trigger outreach

This is self-contained and doesn't touch the regular matching pipeline.
